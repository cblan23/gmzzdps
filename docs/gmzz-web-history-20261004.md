# 历史战斗网站接入与发布

发布地址：https://gmzz.daodaogame.vip

2026-10-04 12:56（北京时间）发布。首页以用户提供的
`daodao_gmzz_home_simple_v4_upload_help.html` 为布局参考，接入现有上传数据库。
发布时收录 2,963 场历史，12 场符合正式统计与排行条件；数量会随上传变化。

## 页面与数据

- 首页展示真实历史数量、有效统计数量及全站最近收录时间，并提供上传说明。
- 历史入口 `/#history` 支持公开角色名或昵称、Boss、职业、难度、统计资格、日期筛选及分页。
- 战斗详情支持团队成员、DPS/HPS/承伤、个人指标、技能汇总、逐次打击分页、交互曲线及分享链接。
- Boss 排行和职业统计沿用有效记录的资格校验。职业统计无样本时显示空状态。
- 匿名角色保持匿名，不能通过隐藏角色名或昵称搜索。公开昵称改名后，搜索使用当前昵称。
- 旧记录缺少有效曲线秒数时使用采样序号，并在页面说明；缺失指标显示 `--`。
- 击败但未确认结算的记录显示“击败 · 未确认结算”，展示未纳入统计的实际原因。

新增接口：`GET /api/v1/dps/public/records`、`GET /api/v1/dps/public/catalog`。
原有统计、排行、详情及上传接口保留。上传转换识别 `time_seconds`，保留曲线来源。

## 查询性能

现有数据库中公开名称查询最初约 11 秒，职业筛选约 7.6–9.7 秒。
改为先筛选战斗 ID，并添加两个公开方式的部分索引及职业索引。
修改后名称查询约 0.002–0.005 秒、无匹配名称约 0.0003 秒、职业筛选约 0.03–0.04 秒。
这些结果来自服务器对现有数据库的查询测量，未扩大前端超时。

历史列表只读取需要的成员列，避免加载成员完整技能 JSON。

## 发布与恢复

线上后端目录 `/opt/gmzz-dps-monitor`，静态目录 `/var/www/gmzz`。
发布前核对两份后端文件的旧 SHA-256，备份整站静态文件及两份后端源码。
静态资源和后端文件分别通过同目录临时文件原子替换，后端重启后检查健康、
历史、目录、排行、详情和职业统计，再更新首页。

本次备份：`/opt/gmzz-web-backups/20261004T045630Z`。
其中 `backend/` 存放旧后端，`site/` 存放原静态目录。
部署自检失败会恢复本轮文件并重启；人工恢复时也可使用这两份备份。

此次部署文件仅为：

```text

/opt/gmzz-dps-monitor/dps_monitor_server.py

```

环境配置、上传记录、授权名单和客户端更新元数据保持现有内容。
