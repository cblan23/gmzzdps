# 主窗口性能预览第一版

范围：只优化显示层，不改 Hook/Npcap 后端、采集事件、统计口径、鉴权、历史文件格式。未打包或发布。

- `hud_render_cache.py`：单帧结果缓存，输入深拷贝，防止嵌套 Boss/玩家字典原地变化造成旧画面。数据、样式、字体、DPI 或 renderer 对象变化立即重新合成；绘制失败不更新缓存。缓存仅保留一帧，避免长战斗不断增长。
- `dps_meter.pyw`：接入缓存；合并密集绘制请求，距上次绘制完成不足 1/30 秒时延后最多约 34ms；回调执行时才读取最新统计快照。事件队列仍按原样完整处理，不删除或合并伤害事件。记录最新/最大绘制耗时（毫秒）。
- 已关闭的技能详情原本已有提前返回，不重复修改。
- 不跳过 presenter 的位置/可见性同步，保留拖动、显示/隐藏、锁定等行为。

验证：72 项 HUD 相关测试通过；12 人模拟数据，100%/125%/150%/200% 缩放下，缓存命中和数据变化后绘制均与原 renderer 输出逐像素相同。
30 次重复帧基准：原合成平均约 26～31ms，缓存命中约 0.002～0.004ms。
该数字只衡量重复帧合成，不代表整条采集链路延迟，也不是实战性能承诺。

新增测试：`test_hud_render_cache.py`。临时基准：`.codex-tmp/benchmark_hud_cache.py`。
完整 1,097 项测试运行中，1,096 项通过，唯一失败为旧断言仍要求 CLIENT_BUILD=.6，实际已发布为 .7；该断言修正后，与缓存测试共 5 项定向复测通过。
本版没有完成独立统计线程/后台归档等大型改造；先验证这版实战表现再扩大范围。
