# 主窗口设计稿实现

视觉来源：用户提供的 `用户附件.png`，保存在 `assets/main_hud_reference.png`。
当前 PNG SHA-256：`84A94EC65B28D0306067DC713E9084CF70ECFC27B69302F9DBD5F1233201B5B5`。

## 素材与实时内容

- Boss 徽记、骷髅和按钮外框使用设计图素材。依最新要求，原关闭按钮替换为置顶，底部为 PVP / 设置 / 锁定 / 置顶，不增加第五个按钮。置顶状态蓝色高亮，点击可取消；退出仍使用托盘菜单。
- 左下角使用项目 `assets/app_logo.png`，叠加金色圆形边框，不替换项目图片。
- 职业符号来自现有 `assets/professions/1200001.png`～`1200007.png`。沿用既有职业色相，直接给内侧图案上色并增加轮廓辉光，不再使用任何圆形底盘。
- 未取得的数据在显示层留空（包括 Boss HP/百分比、个人数值/总量、评分），保留真实 0 和“人机”；不改底层 `None` 语义，也不编造数值。
- 名称、计时、Boss 血量/百分比、个人统计值/总量、死亡次数和全队秒伤全部由 `DpsWindow._layered_main_snapshot()` 提供的当前数据绘制。没有把示例战斗值替换成生产数据。
- 数字字体的字形轮廓取自设计图，组字内容仍可任意变化；新中文角色名由本机雅黑字体动态生成。单张 PNG 不包含所有可能出现的中文/英文字符，因此不把未出现的字体字形宣称为逐像素复制。
- 视觉对比脚本里的示例数据只用于离线验收；脚本不登录、不采集、不写历史或用户配置。

## 显示与交互

设计坐标统一基于原图 `(146,126)-(1130,1130)` 的内容区域；同一缩放因子用于所有元素，数字变化不改变列边界。死亡列关闭后整窗收窄；按实际人数最多直接展示 12 行，正常 12 人团本不需要滚动，底部观众也可见。

按后续反馈，Boss 血条高度增加 8 个设计像素（约 10%），不扩大窗口宽度；Boss 名称与全队秒伤使用同一字体字号，血量/百分比略小，所有文字按实际字形边界纵向居中；左上角计时只保留文字及可读性描边，不绘制背景胶囊。Boss 徽记向右移动增加遮盖。狂暴提示适度放大；原有四档计算与双血池预测保持不变。若模型同时确认两只 Boss，则纵向显示两条同宽血条；阶段目标更替沿用模型的计时与整场统计，不产生第二场战斗。

本人高亮与普通行采用相同文字内边距和列锚点；总伤/总治疗/总承伤移除胶囊背景，使用原稿括号/浅灰字并紧贴秒伤。数字字格统一，每列统一字号。评分标题与值组成紧凑组合，值区预留六位数；数字、“--”和“人机”都居中，人机不显示其数值且不修改原始资料。无目标时血量和百分比占位符在名称后的剩余区域居中。

本人高亮改为从原图蓝色采样形成的平滑圆角渐变、柔和辉光和细描边；不再横向拉伸两像素纹理或包含原示例职业图案的端帽，降低硬边与拼接感。

更新后的显示优先级为：进行中的战斗 > 同一地图内保留的本场结果 > 待战评分预览。收到本人/当前 Boss 的已接受进战斗信号就立即刷新为战斗显示，不等待首个伤害包；底层统计启停和分母不变。结束后不自动回到评分，保留 HPS、仅治疗的队友以及 DT。切换地图时，主窗口立即清空当前数值和保留结果，并防止旧记录的延迟结算重新出现在新地图；历史记录仍正常保存。已验证特殊 Boss 的内部阶段转场沿用原模型的特殊处理，不中断整场统计。手动清空/退出鉴权也清除保留结果。DT 的“改为总承伤”提议已经撤回，保持 DT/s + 对应总承伤。未绑定身份的匿名负 ID 占位槽不参与主窗口人数；真实已识别队友（包括暂时零伤害队友）仍保留。

当前观众角色选择 HPS 时，伤害木桩缺少治疗数据会显示 `--`，并非 DPS 丢失。职业指标入口移除后保留已有角色显示偏好，观众出厂默认仍为 HPS；本轮没有将缺失的 HPS 推算成伤害值。

采用 `UpdateLayeredWindow` 预乘 Alpha 绘制；Tk 负责窗口生命周期和输入。主窗口整体透明度固定 100%，不再提供选项；任何旧 `alpha` 值在启动迁移和保存时强制变为 `1.0`，旧回调也不能重新设置淡出。每像素透明仍保留，不创建不透明矩形背景。锁定时只在原锁按钮位置提供相同外观的可点击解锁区域，主窗口继续鼠标穿透。

设置改为无 tab 的单页：常用显示 / 职业显示指标 / 首领信息 / 外观与缩放 / 快捷操作。按最新反馈恢复职业配置：观众 HPS/DPS，战士 DPS/DT，其余固定 DPS。移除目标 Boss 资料识别、旧版选项及整体透明度入口；其余设置按组排列，可滚动查看。仍被详情/采集使用的兼容数据保留，不删除整个旧配置文件。

首领已损失 HP 的区域加深至近黑色，剩余 HP 保持明亮红色；预警框宽度随文本测量，不保留大块空白。一号信徒双 Boss 初期把现有预警归属者巴尼先生排列在上方；原阶段规则进入安西娅后按同一规则调整顺序，不改双血池与计时算法。

进本身份回归：`OnMsgDungeonReadinessCheck` 的单人计数不能推翻已存在的多人组队证据，防止首个响应队友的身份/评分覆盖本人。已确认本机身份在名单临时刷新时保留，首个有效入战信号立即刷新 HUD。此处修改包解释条件，不改变任何 Hook、Npcap 或发包行为。

HP 回归：已验证的 Boss HP 更新到达后触发主窗口绘制，不额外等待 DPS 汇总定时器；旧时间戳 HP 不能覆盖新值。纠正被误绑到玩家的 Boss 指针时，仅保留同一来源指针实际发布的 MaxHp 字段，避免星象仪者等场景退回“第一笔已掉血 CurrentHp”作为最大值。仍保留异常技能值过滤、场景清理和双 Boss 的血量校验，不按 DPS 推算 HP。

上传确认弹窗优先保留底部按钮空间，并按实际字体、选项换行和内容高度计算弹窗高度，避免 100%～200% DPI 下按钮被挤压裁切；不改变上传权限或身份逻辑。

本轮无新增持久化配置键，继续消费已有 `main_ui_scale`、`font_size`、`alpha`、`show_deaths` 等配置。未修改 DPS/HPS/DT 的取数、DPS 排序、底层战斗判定、采集、卡号鉴权、上传权限或战斗记录口径；显示状态优先级按上文调整。

## 验证

```powershell
py -3 -m unittest test_main_hud.py test_main_hud_behavior.py test_combat_model.py
py -3 tools/preview_main_hud.py
py -3 tools/verify_main_hud_window.py
py -3 tools/verify_settings_upload_ui.py
```

`preview_main_hud.py` 输出原图与渲染结果的 100/125/150/175/200% 明暗底色并排图。
`verify_main_hud_window.py` 使用实际 Win32 HWND 和生产显示适配器检查动态更新、按钮、拖动、透明度、锁定/解锁、死亡列回收、评分预览和 DPI；只创建临时预览窗口并在结束时销毁，不连接游戏或服务器。
