# Npcap 适配边界（2026-09-11）

用户再次明确：迁移只调整数据来源，既有统计、队伍、死亡、Boss 阶段及 UI 规则不应为迁移让步。

- 公共 `network_state.py` 已恢复为基准提交内容，未保留为 Npcap 添加的身份分支或延迟豁免。
- `npcap_parser_adapter.py` 接收已经复制并解析的网络记录，调用原有解析接口，输出既有 identity/profile/event/life 等事件。
- Npcap 本人身份由仅发给本人的 `RetCastSkillSuccessNew` / `OnUpdateTeamGroupSelfProps` 的明确接收实体提供。适配层拒绝用同职业、同技能的其他施法者猜测本人。
- `decode_delay_ms` 在原合同中表示延迟读取游戏内存参数的年龄。网络复制数据没有这种内存读取延迟；真实收包到解码延迟另存 `capture_decode_latency_ms`。统计时刻仍保留原采集时间。
- 切图不再无条件丢弃连续 KCP/RC4/Zstd 流。仍保留实际缺包、断线和解码失败的恢复路径。
- `npcap_entity_metadata.py` 只读复制已收到网络实体的精确模板/类型字段，为旧解析器补上初始化输入；不执行游戏函数。收到受击、血量上限、战斗状态、死亡等事件时也能初始化目标，覆盖本人没攻击的第二个 Boss。已解析对象会重新验证，以检测同实体的阶段模板变化。
- 不把普通目标强行认作 Boss，不生成队友缺失伤害，不把未绑定人机的真实死亡事件随便分配给其他成员。
