# 混合真人/人机队伍 DPS 异常调查与修复

反馈 FBAA5860439E69673D，来源构建 `0.2.3+20260911.7`（v0.2.3c），用户补充场景为3名真人，其余人机。原反馈正文为“有问题”。本轮修改本地模型，不改 Hook/Npcap 采集，不改服务器或既有历史文件。

## 原始反馈可确认的事实

- 记录 `df77ccfb7c80-000094`，Boss模板7102990（子爵夫人），Boss血量34,750,529 / 66,735,474。
- 历史伤害16,281,564、时长1秒、队伍DPS16,281,564；6名参与者DPS分别等于各自整场总伤。
- 同期采集诊断：完整团队回复最后有12名成员，总伤32,049,938；原生采集累计有517条伤害，而当前归档的packet_event_count为0。
- 归档team_cumulative_states中，一部分队员的accepted_damage为0，其他队员的first_time和last_time都等于同一个回包时间。
- 这些事实表明累计值/时间/本场成员状态出现不一致，不能仅归因于真实某次技能伤害极高。

## 复现与本轮修复

当前 `_ingest_team_damage_stat` 在单个成员累计值下降、且不属于已有特定阶段保护分支时，会调用 `_begin_team_counter_reset`。该路径可以清空整场事件和时钟，即使同一个Boss仍在战斗或保持受伤状态。随后同一批其他成员的高累计值进入新的一秒记录，造成DPS与旧总伤接近。

新增测试构造3真人/9人机、同一仍存活的Boss、混合成员server_time字段；回退其中任意成员的值。修改前可复现encounter_id改变，修改后时钟、事件、整队累计值保留。逐个遍历12名成员位置，避免结果依赖回包顺序。

处理策略：若当前Boss明确仍在战斗，或可确认仍存活且受伤，并且没有结束、Boss重置、待切换目标信号，则单人较低回包不足以重置全队，暂不采纳该较低伤害值。保留上一条确认值，不按比例推算、不补加新旧差额；后续恢复单调的累计值按原逻辑继续使用。原有已验证换阶段累计策略保留，真正团灭、Boss重置及新目标仍按原逻辑切场。

此策略在该队员确实独立清零但没有其他可靠依据时，可能暂时无法确认新增伤害；不会用猜测的偏移量修正。增加 `damage_accounting.unconfirmed_team_counter_regressions`，保留最近16条相关证据供后续反馈定位。
