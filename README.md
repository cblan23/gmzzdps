这是 Windows 桌面战斗统计工具，提供队伍 DPS/HPS/承伤、技能明细、Boss 信息和本地历史记录。当前源码默认使用 Windows Raw Socket + 程序自带的 WinDivert 只接收后端，不依赖用户安装 Npcap，也不再主动请求 TeamStats。支持界面显示最多 12 人。兼容性边界与发布验收见 [Windows 内置采集报告](docs/windows-built-in-capture-20260916.md)。

**当前限制：队友数据暂时无法全程实时刷新。团灭和中间 Boss 的官方统计可能延迟到下一次开怪时返回；强烈建议进入副本前启动插件。**

### 发布与实验状态

Release 的源码 ZIP 是对应提交的代码快照。Windows 受保护构建需要现有授权服务及对应构建白名单；标为预发布的附件不能视为已完成线上授权验收。程序未承诺游戏官方授权或账号零风险。

Npcap 被动实验已在“钻头”和五月庄园普通“异化猎犬”的两人样本中观察到：下一场开战时收到上一场团灭阶段统计。阶段表含 `battleID`、成员累计伤害和技能累计；异化猎犬连续复现两次。但这尚未接入正式统计逻辑，不能据此宣称当前版本已实现纯被动、每场完整统计。最后一场不再开怪、十二人覆盖、统一 DPS 时长仍需验证，累计表也不提供逐次命中时间轴。

日志、战斗记录、抓包、环境密钥和独立实验原始证据不随公开发布包上传。

## 使用

1. 启动游戏并进入角色可操作界面。
2. 双击 `启动DPS统计.vbs`，在登录页输入服务器签发的卡号并点击“登录”。
   首次成功登录后，卡号会使用 Windows 当前用户加密保存，下次打开自动带出；配置文件中不会保存明文卡号。
3. 连接游戏后即可开始战斗。主窗口统一为透明悬浮 HUD，最多直接展示 12 人。设置中的“职业显示指标”可选观众 HPS/DPS、战士 DPS/DT；其他职业固定 DPS，队伍始终按 DPS 排序。
4. 点击“隐藏名称”后，所有角色按稳定顺序显示为“玩家1、玩家2……”；再次点击“显示名称”恢复网络封包解析到的角色名。
5. 主窗口每行显示职业、姓名、当前统计值、对应总量和可选死亡次数；战斗记录中的详情仍提供 DPS/HPS/DT、技能、目标和治疗分析。暂未取得的数据在主窗口留空，不补成虚假零值。
6. 程序固定只统计客户端确认的 BOSS 和木桩，不统计普通怪物。
7. 标题栏“反馈”可将问题描述和可选运行摘要提交到服务器；摘要同时包含最近战斗、队伍累计状态和目标锁定状态。
8. 设置为单页，按常用显示、职业显示指标、首领信息、外观与缩放、快捷操作分组。主窗口整体透明度固定 100%，升级会覆盖旧透明度值，Alpha 透明背景保留；仍可调整字体大小、UI 缩放和玩家行遮罩。
   “隐藏/显示快捷键”默认为 `Home`；点击快捷键值可录入 `Alt`、`Ctrl` 组合键。关闭开关保留按键内容，点击“清除”才删除当前按键。
9. 已取消迷你模式。开启“队伍非凡评分预览”后，组队待战阶段显示评分，人机显示“人机”；开战切到战斗数值，同地图战后保留结果，切图清空当前显示但保留历史记录。
10. 底栏为 PVP、设置、锁定、置顶；PVP 暂未开放。点击锁定后主窗口鼠标穿透，只在原锁按钮处提供解锁操作；置顶按钮切换是否保持在上方。
11. 主窗口不占用任务栏；左键托盘图标可恢复窗口，右键菜单可选择“显示窗口”或“退出”，退出会安全停止采集并保存数据。
12. 登录后程序会在后台检查新版本，也可在后台页手动检查；更新文件保存在当前 EXE 所在目录，完成大小与 SHA-256 校验后自动替换并重启。

同一设备从旧版本升级时，新版本登录会自动接管旧版本会话；旧版本会退回登录页。该过程不会重新激活卡号或改变剩余时间。另一台设备仍受单卡单设备和改绑冷却限制。

程序不提供手工修改角色名、游戏 ID、队伍名单或怪物资料的入口。角色与实体资料以客户端收到并解密后的网络封包为准。

## 数据来源

本节及下一节保留了旧 Hook 版的历史链路说明，并非当前默认后端的运行行为。当前采集/解码边界请以 [Windows 内置采集报告](docs/windows-built-in-capture-20260916.md) 为准；结算仍使用既有 v0.3.0 Matcher/PENDING 兜底，不通过主动请求或伤害模拟触发。

- 团队实时总伤来自游戏的 `RetCommonCombatStatisticsByTeam` / `RetDirtyCommonCombatStatisticsByTeam` 逐成员绝对累计值；程序主动请求完整 Common，按网络用户令牌关联队员并转换为本轮增量。
- Boss 首次真实掉血只用于统一冻结所有成员的开战前基线，Boss 血量、队友命中标记、守卫死亡均不会被换算或分配为任何人的伤害。计数器下降或实例切换时，全队同时建立新基线，避免团灭重开夹带上一轮数据。
- 本机精确伤害回调用于 Common 到达前的即时显示以及技能、暴击和目标占比明细；Common 覆盖到相同时段后以逐人绝对值为准，不重复相加。任何已识别技能和目标的绝对金额都不会按总伤比例放大或缩小；团队总伤大于已分类技能和的部分只显示为“未归类伤害”。
- 队友逐技能金额来自游戏阶段/完成表中的逐人、逐技能绝对值。只有该角色的阶段总伤与实时 Common 本轮总伤完全一致时才采用技能表；技能合计小于总伤的精确差额保留为“未归类伤害”，不会比例分摊到任何技能。阶段/完成表始终只核验总伤，绝不改写实时总伤或 DPS；表中没有单次最大伤害时界面显示“--”。
- 治疗逐包来自 `OnMsgHealSyncV2` 的治疗者、目标、技能、总治疗和有效治疗字段；服务器阶段/完成表字段 `17/35` 分别提供玩家有效治疗和逐技能有效治疗。HPS 使用与 DPS 相同的服务器统一战斗秒数。逐包覆盖不足时，总治疗、过量、峰值和目标/响应明细只显示 `--` 或“已观测部分”，不按比例补齐。
- 逐怪伤害只采用带玩家、怪物和伤害三元组的精确回调。团队累计值中缺少目标维度的部分显示为“未分配目标”，不会默认归给主 Boss 或按血量变化推算。
- 角色名称、游戏 ID、队伍成员和场景实体资料从角色、队伍与场景 RPC 中解析；程序不读取 `C7.log`、Lua 堆、本地角色缓存或手工配置的身份数据。
- 怪物当前血量来自目标实体的 `OnMsgSyncCurrentHp`，最大血量来自 `OnMsgSyncCurrentMaxHp` 或战斗属性 21；若程序在战斗中途启动，则以首次捕获的当前血量作为进度条临时 100% 基线。目标 ID 由伤害/受击封包关联，本人或队友血量不会进入怪物血量区域。
- 怪物模板号与客户端导出的 `MonsterData.BossType=3` 清单逐项匹配；命中清单才作为 BOSS/木桩统计，并直接使用该模板对应的中文名称和等级。运行时类型、血量、音乐、名称文字均不单独决定目标是否进入统计。
- 技能名称来自客户端 `SkillDataNew` 中文本地化表。
- 职业与技能图标从本机 C7 的 KMF、`local.cache` 和 IoStore 资源解包，不使用网络图片。
- 当前已生成 7 个职业原图、943 个精确封包技能 ID 原图，以及 435 个只在唯一同名原图时生成的效果子技能别名，共 1378 张技能 PNG。
- 审判者途径的技能表没有 `SkillIcon` 字段，程序会从客户端自带的 `Arbitrator` 图集按封包技能 ID 读取原图。

统计参与者以“谁对当前统计目标造成了有效伤害”为准，不预先创建零伤害队伍成员。团队成员数量不写死，六人和十二人团队使用同一套动态名称、职业和技能资料解析；已经对目标造成的伤害不会因退队而从本轮结果消失。

## 采集与安全退出

- 统一采集入口为客户端解密、解压并完成 msgpack 解码后的 `doraemon::script::ScriptEntity::do_message`。
- 采集器支持 nil、布尔、正负整数、Float32/Float64、UTF-8 字符串、二进制、数组、映射和扩展类型，并保留与统计相关的 RPC 明文日志供后续字段适配。
- 连续 10 秒没有伤害后保存本轮快照；同一 BOSS 在 60 秒内恢复伤害仍续算原战斗，以覆盖转阶段、复活和短暂无敌。新 BOSS、场景切换或确认重置会开始新一轮。
- 原始解码 RPC 保存在 `logs/network_*.jsonl`。
- 界面消息泵每批最多处理 64 条且单批预算约 12ms；持续战斗有积压时会主动把控制权交回界面，消息按原顺序保留并在后续批次继续处理。
- 正常关闭窗口会恢复游戏函数并释放采集内存。不要使用任务管理器强制结束统计器。
- 游戏包含 ACE，任何运行时采集方案都可能被拦截或带来账号风险。

## 构建

构建运行 `build_exe.ps1`，固定使用 Windows Raw Socket；编译包携带 WinDivert 2.2.2 驱动与 LGPL/GPL 许可证，只以 `SNIFF + RECV_ONLY` 模式补足 IPv6 或 Raw Socket 被阻断的情况。不需要提供 Npcap 安装器，也不再提供 Npcap 兼容构建。编译包仍为原地运行的便携 EXE，每次启动请求管理员权限。

受保护构建使用独立的 `-ProtectedRelease` 开关，不要求同时具备 Authenticode 证书。先在服务器上运行 `server/provision_capability_key.py`，私钥只保存在服务器；将命令输出的公钥和 Key ID 传给 `build_exe.ps1 -ProtectedRelease -CapabilitySigningKeyId ... -CapabilityPublicKey ...`。受保护包不会包含 `runtime-profile.dev.json`，只有通过服务器签名租约续期后采集才会继续运行。
