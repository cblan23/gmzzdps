# v0.2.3 反馈修复进展

更新：下述修复已进入 `0.2.3+20260911.3` 正式修复包，白名单已同步。新增的 Boss 等级、血量归属与多阶段计时保护详见 `v0.2.3-r3-validation.md`。本次新包尚未替换公网在线更新。

记录日期：2026-09-11。用户要求先记下并继续发布当前修复包。

## 1. Boss 预警提醒没有跟随血条

- 用户原话：“boss血量预警提醒并没有跟着血条走”。
- 状态：源码已修复并验证；尚未包含在已发布的 `0.2.3+20260911.2` 包中。
- 原因：新版绘制将预警框固定在右侧，又将箭头限制在文字框内；另外，0% 被 `or 0.82` 错当成默认 82%。
- 修复：预警框沿理论血量标记移动；文字框在边缘避让计时文字，箭头仍可覆盖完整血条。血量填充和箭头共用同一内侧坐标。文字框与箭头的悬停区域同步更新。

## 2. 八分钟狂暴的计时不一致

- 用户原话：“时间计算有问题 狂暴8分 现在剩余时间和你显示的时间加起来超过8分钟了”。
- 状态：源码已修复并验证；尚未包含在已发布的 `0.2.3+20260911.2` 包中。
- 原因：主窗口使用已校准的持续时间，倒计时却用本机当前时间减服务器起始时间；实际记录 `6e97b5613b46-000001` 中两端时钟约差 7.657 秒。
- 修复：普通狂暴倒计时与主窗口共用 `model.duration(now)`；校准后不再保留旧的时长上限。剩余时间向上取整，与已用时间的向下取整配合，狂暴前显示合计为 08:00。
- 同一未暂停的狂暴计时阶段、倒计时尚未结束时，已用时间与剩余时间应符合 480 秒总时限；需区分完整战斗耗时和可能独立起算的阶段计时，避免两个不同起点的数值造成误解。
- 保留星象仪者的第二阶段独立起算规则，其提示详情使用“阶段已用时间”明确区分。不修改 DPS/HPS/DT 数据采集或伤害数值。

## 3. 主窗口高度与玩家列表滚动

- 用户新增要求：右下角可拉伸高度，显示不全的玩家区域可滚动，最少显示 1 人。
- 状态：源码已实现并验证。
- 右下角增加小型高度拖动柄；上下拖动按整行调整，可见人数为 1～12。窗口宽度和左上位置保持不变。
- 中间玩家区域支持鼠标滚轮；出现溢出时显示细滚动提示，Boss 区和底栏保持固定。锁定时不启用拖动或滚动。
- 新配置 `main_visible_rows`：默认 12，合法范围 1～12，松开拖动柄时保存，重启恢复；不删除旧配置或战斗记录。
- 只改变可见范围，全队伤害、治疗和承伤仍计算所有参与者；非战斗评分预览也能滚动。
