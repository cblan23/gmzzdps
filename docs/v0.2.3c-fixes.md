# v0.2.3c：Hook 本人身份与成员保留修复

本文记录 `.6` 中间测试包。最终发布为 `.7`，见 [战斗记录修复及最终发布记录](v0.2.3c-history-repair.md)。

用户明确要求暂停 Npcap 切换，先恢复 Hook 修复“本人消失/被同职业队友替代”。Npcap 源码保留，正常入口及默认构建恢复 legacy；显式被动构建仍可使用。

版本：0.2.3c；构建：0.2.3+20260911.6。更新日志采用用户确认的六条修复，并补充 Boss 等级旁显示名称；未发布在线更新。

## 已复现的问题

1. 已确认本人和同职业队友后，下一份 Common 回包只有队友。原代码把“本人行缺失”认作“进程内换角色”，将队友 token 绑定到本人实体 ID，并发出 actor_merge；主窗口和战斗详情都可能少人或串名。
2. Common 回包暂时缺少一个已有队员时，统计自举名单会删除该队员，即使没有任何离队通知。
3. 尚未确认本人时，已知队友先放出同一技能，随后本人技能成功回执到达，旧时间相关匹配会将队友认作本人。
4. 已确认本机实体、尚未确认本人 token 时，一份只有已知队友的回包会错误认领该 token。

## 修复

- 统计回包遗漏本人不再触发身份替换。只有原生 local_player_id 确实变更，才开启角色切换候选验证；已知队友和 AI token 不参与替代候选。
- 同一个身份后续正常再次出现时，关闭待切换状态。保留已测试的正常换角色与同角色实体变化流程。
- 缺少成员的统计回包保留既有名单，明确的加入/退出消息仍负责成员变更。
- 同技能时间相关匹配不能选择已知队友或投影。拒绝匹配时保留未归属的本人施法记录，等待明确身份，避免丢失正确绑定机会。
- 同时包含此前单独授权的团灭重开死亡清理、确认胜利归档不被退出触发原因覆盖两个修复。
- 修复本人身份确认前收到的新评分丢失/被旧缓存覆盖；最新本人评分同时更新实时数据和队伍缓存。
- 清理战斗记录弹窗底部按钮固定可见，选项区域滚动，窗口按宿主尺寸约束。
- Boss 等级右侧恢复名称，长名称省略；双 Boss 独立显示名称，保留头像与血量布局。
