# 更新文件分发后续步骤

新ECS现为数据库/API唯一写入源，旧机保留QQ机器人和维护执行；DNS权威记录已改新ECS。当前3Mbps不适合多人共享大文件，用户已同意接OSS/CDN，但尚无可用Bucket/域名/云API授权。

建议杭州OSS私有Bucket存放以build_id区分的不可变EXE，CDN使用专用下载子域名并开启私有OSS回源授权和Range回源。EXE关闭内容改写/自动压缩，发布前校验完整长度与SHA256及分段下载。更新元数据API保持动态，不缓存授权、卡号、身份或战斗写入接口。

需要用户控制台提供：已创建Bucket名称和地域、CDN下载域名及CNAME，或给新ECS附加限定Bucket上传/读取权限的RAM角色。不让用户发送长期AccessKey或QQ密码到聊天。

客户端兼容边界：旧版下载器有300秒总时限，且默认urllib可能跨域转发Authorization；不能简单将带鉴权的旧下载API全部302到OSS/CDN。新下载路径需剥离服务Authorization、限制HTTPS下载目标，保留最终哈希校验。旧客户端可保留源站兼容路径或从浏览器手动安装一次新版，再使用CDN更新。

已存在本地r2包完成续传/超时修复，但它尚未接入CDN，也未包含其后修复的混合队伍DPS回退保护。下一次正式构建必须重新确定构建号和日志，不能把旧r2当成含所有修复的成品发布。
