# v0.2.3d 发布后下载缓慢

用户在其他电脑复现；本机上传 SSH 及 HTTPS 下载也出现慢速。已停止用于成品复核的本机与远端额外 HTTPS 下载，避免占用真实用户带宽。

## 停止额外下载后的 15 秒采样

每 5 秒读取 `/proc/net/dev` 和 `/proc/net/snmp`：

| 窗口 | eth0 出网 Mbps | OutSegs | RetransSegs | 重传段 / 发出段 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 1.677 | 976 | 233 | 23.9% |
| 2 | 1.581 | 888 | 180 | 20.3% |
| 3 | 1.535 | 1007 | 189 | 18.8% |

此比率不是链路真实丢包率；重传可能由丢包、严重乱序或延迟等触发。网卡驱动 rx/tx drop 计数未增加，不能据此排除主机外的丢弃或延迟。

两条仍在传输的 HTTPS 连接分别有约 1.45 MB / 5.69 MB、0.29 MB / 2.01 MB 重传字节；拥塞窗口只有 4 和 2。正常客户端可能因此获得很低的有效下载吞吐。

系统负载 0.48 / 0.54 / 0.40，可用内存 771488 kB，没有证据表明 CPU 或内存资源耗尽。

`nginx -T` 未发现下载 `limit_rate` 或 `proxy_limit_rate`。存在的 `limit_req` 属于反馈接口。下载处理直接读磁盘、每块 256 KiB 写入响应，没有代码级延时或限速，下载不是数据库查询流。

## 能确认与不能确认

能确认：当前公网有效传输慢并伴随显著 TCP 重传，多端复现；不是只在单台用户电脑出现。81,046,528 字节的更新包被低吞吐放大了等待时间。

不能确认：实际购买的公网带宽值、是否触发云端限速、哪一段网络丢弃或延迟。当前主机出网样本不能代替阿里云带宽上限和丢包监控。

需要云控制台对照 2026-09-12 09:56～当前的公网带宽配置、出入流量峰值和带宽/PPS限额丢包指标。已有 SSH 访问不等于拥有阿里云控制台/API 监控授权。

## 继续核查 1.5～1.7 Mbps 的来源

- 这是 eth0 发送字节计数差除以采样秒数、再乘 8 得到的整机流量，包含重传及其他业务流量；不是读取到的公网带宽配置，也不是某个用户的纯文件下载速度。
- 新的三个 5 秒窗口分别为 1.453、1.460、1.477 Mbps，说明之前的 1.5～1.7 只是当时的观测区间。
- `tc -s qdisc show dev eth0` 为 fq_codel，未配置整形 class/filter；累计 dropped、overlimits、backlog、drop_overlimit 均为零。
- `ip -s link` 的 RX/TX errors/dropped 均为零；`ethtool -S eth0` 的 rx_queue_0_drops、tx_queue_0_tx_timeouts 均为零。
- TCP 使用 cubic；最新大下载连接仍有约 1.51 MB 重传，累计发出约 7.31 MB，拥塞窗口为 1，应用尚有约 121 KB 未发送。存在待发数据而网络窗口很小，支持传输拥塞/重传约束吞吐，不能把慢速直接归因为应用没有及时提供文件字节。
- 系统负载进一步降到 0.12 / 0.30 / 0.33，可用内存约 792 MiB。
- 实例元数据列出 `instance/max-netbw-egress` 和 ingress，原始返回均为 `204800`。本次未取得官方字段单位说明，且规格网络能力不能直接替代公网购买带宽，不将此值转换为公网限速结论。
- 本机未配置 Aliyun CLI 凭证；此前元数据未配置 RAM role。无法凭现有 SSH 访问直接读取 EIP/ECS 的公网带宽订单值及云侧丢包监控。

结论边界：已排除主机显式流量整形及网卡本地丢弃，确认重传伴随拥塞窗口收缩；尚不能判定云端带宽封顶或具体链路故障。下一项需要的具体材料是 ECS 实例网络信息中的公网带宽值，以及同一时段公网出流量和限额丢弃监控。不能声称已查到固定 1.5/1.7 Mbps 限速。
